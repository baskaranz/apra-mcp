The problem

Autonomous agents are now making regulated decisions

Australian banks, insurers and super funds are putting AI agents into production: lending assistants, claims triage, customer-service copilots, often from third-party vendors with no source access.

Under CPS 230 and CPS 234 the Board holds ultimate, non-delegable accountability (CPS 230 Para 19, CPS 234 Para 13). An agent that approves a coerced loan, leaks a customer's TFN, or invents coverage creates direct director liability and can trigger mandatory 24-hour or 72-hour APRA notifications. Risk teams have had no fast, repeatable way to interrogate these agents against the standards. That is the gap.

The honest limit

63 obligations. A chat probe can see about eleven.

This is the slide a competitor won't show, and the reason to go deeper. A conversational black-box probe can only test what an agent says and does. Today it meaningfully assesses around 11 of the 63 clauses across both standards.

Observable — a probe can test these

Unauthorised commitments, data and PII leakage, prompt injection and jailbreaks, system-prompt and IP extraction, cross-session data bleed, output integrity and unfair decisions, resilience under malformed input, logging admissions.

Governance — a probe cannot see these

Board accountability, BCP and tolerance testing, material-service-provider contracts and offshoring, information-security capability and policy framework, asset classification, independent control testing, internal audit. These need document and control review.

Phase 2 · the ask

A deep MCP / agent

Replace "a UI that runs a few checks" with an agent that reasons across the whole standard and orchestrates every assurance method. Four moves.

Go wider on behavioural coverage

Add the high-signal stages we're missing today, each mapped to a clause as a risk indicator (table below).

Go deeper with adaptive probing

An LLM-driven agent researches live clause text through MCP tools, crafts adaptive multi-turn attacks, follows the agent's weaknesses, and reasons about whether a response is really a breach, instead of regex-matching scripted scenarios.

Go MCP-native

Expose the capability as MCP tools so it drops into the entity's stack: a runtime in-band guardrail that audits a draft action before dispatch, a CI release gate, and assurance inside the client's own agents and copilots.

Close the governance gap

A control-review companion ingests policies, BCPs, MSP contracts and control-test evidence, runs a structured questionnaire, and maps documents to clauses. One agent covers behavioural probing and control review together.

Why an agent, not more UI

The vehicle is the advantage

  • Reasoning, not regex. It adapts attacks and judges responses in context; clause mapping becomes an explained inference rather than a brittle keyword match.
  • Grounded. It queries the live regulation corpus through MCP tools, so every finding cites real clause text.
  • Embeddable. MCP is the protocol these agents already speak, so assurance rides into runtime, CI and copilots with near-zero integration.
  • Continuous. It turns a one-off audit into always-on prudential assurance.

What keeps it defensible

Integrity guardrails

  • Chat findings are risk indicators, not legal conclusions. Clause applicability depends on the entity, service, materiality and control context.
  • Every finding carries evidence, limitations, date and version.
  • Human-in-the-loop: outputs assist accountable risk teams under CPS 230 Para 19 and CPS 234 Para 13. They are not a certification or a regulatory filing.
  • SSRF-safe, read-only, synthetic-fixture probing with a hard safety circuit-breaker on real secret leakage.
